API 与事件

rvc_next.api 是 FastAPI 一端：把 HTTP 请求解析成核心层的 Record 模型，调用一个核心方法，再把结果原样返回；服务器到浏览器的推送走 socket.io。它不导入 rvc_next.engine（整体架构中的分层规则由 tests/test_architecture.py 守住），也不含业务逻辑——最大的路由文件 routers/models.py 也只是一串“一行调用核心”的路由。

本页面向需要增删接口、调整安全策略或新增事件的维护者：应用如何组装、REST 约定、上传与媒体、访问控制、事件与载荷、从 OpenAPI 生成 TypeScript 类型，以及服务器启动时的端口选择。

应用的组装

api/app.py 的 create_app(services, bound_host, bound_port, extra_hosts, serve_ui, api_prefix) 依次（下文的路径都在 api_prefix 之下，默认为空）：

  1. 建 RvcNextAPI（FastAPI 子类，见下文“事件进入 OpenAPI”），docs_url="/docs"、openapi_url="/openapi.json"、关闭 ReDoc，并设 separate_input_output_schemas=False；把 services 存到 app.state.services。
  2. install_error_handlers(app)：任何 RvcNextError 都变成 {"code", "message", "detail"}。
  3. 依次挂载 ROUTERS 中的 13 个路由模块，统一前缀 /api；各路由自带 /v1/<资源> 前缀，所以完整路径是 /api/v1/...。
  4. 在 /ws 挂载 socket.io（SocketBridge.asgi_app()）。
  5. 中间件：server.allowed_origins 非空时加 CORSMiddleware；总是加 GZipMiddleware(minimum_size=4096) 与 SecurityMiddleware（后加者在外层，所以安全检查最先执行）。
  6. 最后挂载 SPAStaticFiles 到 /，只有找到 webui/dist/index.html 时才挂；没有构建产物时只记一条警告，API 照常工作（开发时由 Vite 提供页面）。

生命周期（lifespan）只负责启动和停止 socket 桥。服务本身由调用方创建与关闭：rvc-next webui 用 build_services(start_background=True) 启动任务调度和空闲卸载，再交给 create_app；测试则传入自己的 Services。这样同一个 create_app 既能服务真实进程，也能在 TestClient 里跑。

嵌入模式（embed.py 的 RvcNextServer）走同一条路：build_services(data_dir, config_dir, settings_path, settings_overrides, start_background=True)，绑定端口，create_app(..., api_prefix=...)，在后台线程运行 uvicorn，并像 rvc-next webui 一样写 server.json。normalize_prefix() 把 voice、/voice/ 都规范成 /voice；SecurityMiddleware 按前缀判断受保护路径。用法见 嵌入到其他程序。

依赖注入只有一个：api/deps.py 的 ServicesDep = Annotated[Services, Depends(get_services)]，从 request.app.state 取服务。没有全局服务定位器（InvokeAI 的做法），因此一个路由依赖什么写在它的签名里，测试换掉 app.state.services 即可。

REST 约定

约定做法原因
一资源一路由api/routers/<资源>.py，APIRouter(prefix="/v1/<资源>", tags=[...], responses=ERROR_RESPONSES)生成的客户端按 tag 分组，错误形状对每个路由都已声明
显式 operation_id每个路由都写，如 list_models、run_experiment生成的类型与日志里的名字稳定，不随函数改名变化
请求、响应都是 Record路由签名直接用核心层模型；少数仅 API 需要的小模型（AppMeta、ImportSession、ClearedJobs…）就地定义在路由文件里API 的 JSON 与 CLI 的 --json 形状一致（tests/cli/test_cli.py::test_model_json_matches_api_shape）
普通 def碰磁盘或数据库的路由都写成同步函数Starlette 把它们放进线程池，事件循环不被阻塞
只有上传是 async先异步把请求体写进临时文件，再 run_in_threadpool 交给核心见下文“上传与媒体”
长操作返回 Job转换、分离、训练、下载、合并、提取、导出、建索引都立即返回一个 Job 快照进度随后由 job_updated 推送，HTTP 请求不挂起
列表分页GET /jobs、GET /outputs 用 cursor + limit（分别夹在 1–200、1–500），返回 JobPage/OutputPage 的 next_cursor历史可能很长

错误由 core/errors.py 定义，api/errors.py 只做映射，HTTP 状态码与 CLI 退出码来自同一个异常类（完整表见整体架构）。ERROR_RESPONSES 为 400/403/404/409 声明 ErrorResponse 模型，生成的客户端因此知道错误体的形状。几点 API 特有的约定：

  • NotLocalError（not_local，403，定义在 api/deps.py）只在 API 里存在：揭示文件（只对服务器本机的浏览器有意义）。
  • SecurityMiddleware 直接写出的错误（bad_host 400、bad_origin 403、auth_required 401）不经过异常处理器，但形状相同。
  • FastAPI 自己的请求校验错误仍是 422 + detail 数组；前端 toError() 把它折算成 invalid_input。
  • POST /convert 与 POST /separate 拒绝 output_dir/overwrite：写到任意目录、覆盖文件是命令行（受信任的本机用户）专属的能力。

路由顺序

routers/models.py 中固定路径（/catalog、/imports、/indexes、/base、/separation、/legacy-roots…）全部写在 /{voice_id} 之前。FastAPI 按注册顺序匹配，新增固定路径时必须放在通配路由上面，否则会被当成一个音色 id。outputs 的 POST /zip 同理。

实时变声的控制也是 REST。 socket 只承载服务器推送（live_state、live_stats、devices_changed），客户端从不经 socket 发命令。这延续了 InvokeAI 与 SD Model Hub 的设计：所有改变状态的操作都有 HTTP 状态码、错误形状和 OpenAPI 描述，可以用 curl 或 CLI 复现；socket 断线也不会丢命令。

导入的一步式接口。 PUT /models/import 与 POST /models/import-path 是对导入会话的封装：计划“有把握”（confident）时直接提交并返回 ImportResult；需要用户决定时抛 ConflictError，409 的 detail.plan 里带着计划，脚本可以据此改用会话接口提交决定。会话接口（POST /imports → PUT /imports/{sid}/files 或 POST …/paths → GET /imports/{sid} → POST …/commit）是同步的：提交直接返回 ImportResult，而不是一个任务（复制是本地操作，最慢的分离模型加载检查也只要几秒；见 AGENTS.md §8）。识别与配对规则见核心服务。

上传与媒体

上传是原始请求体的 PUT，不用 multipart。 api/uploads.py 的 spool() 把 request.stream() 按块写入 <目录>/.incoming/<id>.part，出错或断开就删除；路由随后用 read_chunks() 把文件按 1 MiB 块交给核心（services.audio.upload、imports.add_upload、models.set_index_upload…），无论成败最后都删除临时文件。文件名放在查询参数里（name 或 filename，最长 255）。

这样做的原因：

  • 音频和模型动辄几百 MB，multipart 解析要么整块进内存，要么依赖 python-multipart 的临时文件策略；原始请求体可以边收边写，内存占用恒定。
  • 前端用 XMLHttpRequest 直接 send(file)，能拿到上传进度（fetch() 拿不到）。
  • RAW_BODY 作为 openapi_extra 写进 schema，声明 application/octet-stream，生成的类型因此知道这些端点收二进制。

媒体用 FileResponse。 api/files.py 的 audio_response() 按扩展名给出 MIME，Cache-Control: private, no-cache，Content-Disposition 同时写 ASCII 回退名和 RFC 5987 的 filename*（中文文件名下载不乱码）；?download=true 时为 attachment。FileResponse 支持 Range，浏览器在长音频里拖动进度条不必下载整个文件。波形不在浏览器解码：peaks 端点返回服务器算好并缓存的峰值（默认 1024 点）。

打包下载：POST /outputs/zip 以 StreamingResponse 边压缩边发送，不在服务器落地 zip 文件。

访问控制

访问控制分两层：SecurityMiddleware 处理“谁能连进来”，路由里的 require_local 处理只对本机浏览器有意义的操作。

SecurityMiddleware

api/security.py 是纯 ASGI 中间件，HTTP 与 WebSocket 都经过它。三项检查依次进行：

检查规则防的是什么
Host绑定在回环地址时，Host 头必须是 localhost、127.0.0.1、::1、绑定的主机名或 extra_hosts（按引用保存，之后加入的名称立即生效，RvcNextServer.allow_host() 即靠这一点）；否则 400 bad_hostDNS 重绑定：恶意网页把自己的域名解析到 127.0.0.1 后调用本机 API
Origin非安全方法（GET/HEAD/OPTIONS 以外）和所有 WebSocket 握手：有 Origin 时必须等于页面自己的源、在 server.allowed_origins 中，或与 Host 同主机端口；没有 Origin 时 Sec-Fetch-Site 只能是 same-origin、none 或缺省。否则 403 bad_origin跨站请求伪造：别的网页在用户浏览器里对本机服务发 POST/DELETE
访问令牌设置了 server.access_token 时，/api/、/ws/、/openapi.json、/docs 下的请求必须带令牌；/api/v1/app/health 例外。否则 401 auth_required局域网或公网上的其他人

令牌可以放在三处（request_token() 依次查找）：Authorization: Bearer …、rvc_next_token Cookie、?token= 查询参数。比较用 hmac.compare_digest。Cookie 的存在是为了 <audio src> 这类浏览器自己发出的请求——它们无法附加请求头。health 公开，是为了让页面外壳在没有令牌时也能加载，读到 auth_required: true 后弹出 AuthDialog 向用户要令牌。

WebSocket 被拒绝时以关闭码 1008 断开。中间件读取的设置都是函数（lambda: services.settings.settings.server.access_token），所以在设置页修改令牌或允许的源立即生效，不必重启。

令牌是可选的：绑定到非回环地址、或用 extra_hosts 接受公网主机名时都不要求它，rvc-next webui 和 RvcNextServer 只在日志中警告。公开部署的保护（防火墙、VPN、带身份验证的反向代理）由用户自己负责。

本机客户端与服务器路径

判定定义（api/deps.py）用在哪里
is_local客户端地址是回环地址，且 Host 是回环名称（内网穿透和同机反向代理转发的公网主机名不算；测试中的 testclient 也算）AppMeta.local；LocalDep 保护的 reveal（在服务器的文件管理器里显示文件）

通过中间件的客户端都可以指名服务器上的路径（浏览、解析音频路径、按路径导入模型或索引、新建实验或修改数据集、导入旧实验、添加旧版 RVC 安装等）。只有 reveal 只认本机：远程浏览器没有意义去打开服务器桌面上的文件管理器。

音频输入要落在 paths.browse_roots 之内：GET /audio/browse、POST /audio/resolve-path，以及 POST /convert、POST /separate 中 kind == "path" 的输入（路由调用 services.audio.check_refs），越界时 400 invalid_path，detail.roots 列出允许的根。这一检查只在 API 里做——命令行由本机用户直接运行，视为可信，可以读任何路径。模型导入、数据集文件夹等路径不受 browse_roots 约束。

socket.io 与事件

桥接

sequenceDiagram

api/sockets.py 的 SocketBridge 包装 socketio.AsyncServer(async_mode="asgi")：

  • start() 订阅事件总线。LocalEventBus 在发布者线程上同步调用处理函数，而发布者多半是任务线程或 worker 输出的读取线程，所以处理函数只做一件事：loop.call_soon_threadsafe(queue.put_nowait, event)，把事件交给事件循环。一个后台任务 _pump() 再逐个 emit，单个事件序列化失败只记日志。
  • 流量只有服务器到客户端，广播给所有连接；没有房间，也没有客户端事件处理器（单用户应用）。
  • 连接时（_on_connect）在设置了令牌的情况下验证：先看握手 auth.token，再退回 Cookie、Authorization 头或查询参数。Origin 检查已由外层中间件完成，所以 cors_allowed_origins="*"。
  • asgi_app() 用 route_path(scope) 规范化挂载后的路径，再交给 engineio 匹配 /socket.io，以兼容新旧 Starlette 对挂载前缀的不同处理。客户端连接的是 <部署根>/ws/socket.io。

事件携带快照。 每个事件都是完整的 Record 值（例如 JobUpdatedEvent 里是 job.model_copy(deep=True)），绝不是 worker 还在修改的活对象：序列化发生在稍后的事件循环上，而那时任务线程可能已经改了进度。快照也让客户端无需追溯历史——收到即可替换。

事件与载荷

事件类定义在 core/events/models.py，都继承 EventBase 并设置 __event_name__；EventBase.get_events() 递归收集所有具名子类。

models_changed 的 id 并不都是音色 id：索引收件箱发 index:<id>，底模发 base:<slug>，导入的分离模型发 user-<slug>（也是它作为分离预设的 id）。前端目前只按 id 使详情失效，并不区分类型；需要区分时看前缀即可。

为什么高频数据不进查询缓存

live_stats（10 Hz）、train_metrics 与任务进度放在 Pinia store 里，而不是 TanStack Query 的缓存：缓存的每次 setQueryData 都会通知所有观察者并做结构共享比较，高频写入会让无关组件反复重算。缓存只保存“REST 能重新取回”的状态，见 Web UI。

事件进入 OpenAPI

api/openapi.py 的 RvcNextAPI.openapi() 在 FastAPI 生成的 schema 之后，把每个事件类的 JSON Schema（mode="serialization"）加入 components.schemas，把嵌套的 $defs 提升为同级组件，再加一个 ServerEvents 对象：属性名是事件名，值引用事件 schema。组件按名排序，保证生成结果稳定。

这样 socket 载荷与 REST 共用同一份类型来源：前端的 ServerEvents 类型（api/types.ts）直接从生成的 schema 派生，socket.on('job_updated', ({ job }) => …) 中的 job 就是 Job 类型。tests/api/test_api.py::test_openapi_lists_events 检查事件确实出现在 schema 里。

从 schema 生成 TypeScript

flowchart LR
    A["create_app(serve_ui=False)<br/>scripts/generate_openapi.py"] -->|"stdout"| B["webui/openapi.json<br/>（临时，git 忽略）"]
    B --> C["param_specs()<br/>scripts/dev.py"] --> D["src/api/paramSpecs.ts"]
    B --> E["bun x openapi-typescript<br/>--default-non-nullable false"] --> F["src/api/schema.d.ts"]

python scripts/dev.py typegen 做三件事：

  1. 运行 scripts/generate_openapi.py：在临时数据目录、空 environ 下 build_services()，create_app(serve_ui=False)，打印 app.openapi()。不启动服务器、不读用户设置，所以任何机器上结果都一样。
  2. 从 schema 中取出 VoiceParamsModel 与 StreamParamsModel（PARAM_MODELS），把每个字段的 type、default、minimum/maximum、enum、description 写成 src/api/paramSpecs.ts 的 PARAM_SPECS。openapi-typescript 只生成类型，而参数面板需要具体数字；这一步让滑块的范围、默认值和帮助文字只有一个来源——核心层 core/params.py 的字段约束。
  3. 用 openapi-typescript 生成 src/api/schema.d.ts。--default-non-nullable false 让带默认值的请求字段保持可选（客户端可以省略）。

两个生成文件都提交进仓库。typegen-check（dev.py check 的一部分，也在 CI 中运行）重新生成后执行 git diff --exit-code，API 改了却没重新生成就会失败。

与类型形状有关的三个设定：

  • Record 设置了 json_schema_serialization_defaults_required=True：带默认值的字段在响应里总会出现，所以 schema 把它们标为必填，生成的类型不会处处是 ?。
  • separate_input_output_schemas=False：大多数模型只生成一个 schema，而不是 -Input/-Output 两份。FastAPI 仍把 Dataset、FitSettings、SpeakerEntry 拆成两份，api/types.ts 读取 -Output 形状、发送时用 -Input。
  • 事件 schema 用序列化模式生成，但事件类里带默认值的字段在 TypeScript 中仍可能是可选的；api/types.ts 中的注释记录了这一点（服务器实际总会发送）。

静态页面

api/static.py：

  • web_dist_dir() 通过 rvc_next.webui.__path__ 定位 dist/，而不是相对当前目录或写死的路径，所以源码检出与安装后的 wheel 都能找到。dist/ 被 git 忽略，作为包数据（pyproject.toml 的 "rvc_next.webui" = ["dist/**/*"]）由 scripts/build_wheel.py 构建后打进 wheel。
  • SPAStaticFiles 对 assets/ 下的文件发 Cache-Control: public, max-age=31536000, immutable（Vite 产物文件名含内容哈希，可以永久缓存），其余文件（主要是 index.html）发 no-cache，保证升级后浏览器拿到新的入口。
  • 未知路径只在请求 Accept 含 text/html 时回落到 index.html。拼错的资源或 API 路径因此仍然得到 404，而不是一页 HTML（这修正了 InvokeAI 的做法里“任何路径都回 index.html”的问题）。前端用 hash 路由，正常导航本就不需要回落。

启动、端口与 SERVER_READY

rvc-next webui（cli/commands/webui.py）的顺序：

  1. build_services(start_background=True)；主机、端口、严格模式、是否打开浏览器取命令行参数，缺省时取 server.* 设置（默认 127.0.0.1:7868）。
  2. 绑定非回环地址时先警告（不要求 server.access_token）。
  3. bind_first_free_port(host, port, strict=…) 自己绑定监听套接字：从配置端口开始，遇到 EADDRINUSE/EACCES（以及 Windows 的对应码）就试下一个，最多 20 个、不超过 65535；strict 时只试一个；端口 0 交给操作系统挑。Windows 上设 SO_EXCLUSIVEADDRUSE（防止别的进程绑定同一地址端口），其他平台设 SO_REUSEADDR（TIME_WAIT 期间也能快速重启）。全部失败时退出（码 3）。
  4. create_app(…, bound_host=host, bound_port=实际端口)，uvicorn.Server(config).run(sockets=[sock])——把同一个套接字交给 uvicorn。
  5. 运行前写 server.json（host、port、url、pid，经临时文件原子替换），向 stdout 打印 SERVER_READY url=http://…，按设置延时 0.8 s 打开浏览器；退出时只删除自己写的 server.json（比较 pid）。

为什么绑定而不是探测

InvokeAI 先 connect 探测端口，再在服务加载完后让 uvicorn 绑定。探测只能发现“有人在监听”的端口，Windows 的保留端口段这类“没人监听但绑不上”的情况会被误判为空闲；探测和绑定之间还有一整段启动时间，别的进程可以抢占。直接绑定是唯一可靠的答案，而把测试过的套接字原样交给 uvicorn，就不存在空档。SERVER_READY 一行和 server.json 则让启动器、脚本和其他程序得知端口变化——日志里的警告对机器不可读。--strict-port 用于端口映射固定的部署（反向代理、容器），那里悄悄换端口只会掩盖问题。

read_runtime_file() 会检查 pid 是否存活，过期的文件视为不存在。任务服务在启动时也借助它判断数据目录是否已被另一个存活的服务器占用（见核心服务）。开发模式下 scripts/dev.py dev 以 --no-open --strict-port 启动 API，并让 Vite 通过 RVC_NEXT_BACKEND 代理过去（见 Web UI）。

新增一个接口

  1. 在核心层写方法，参数与返回值是 Record；需要的错误用 core/errors.py 中已有的类。
  2. 在对应的 api/routers/<资源>.py 加路由：写 operation_id，签名用 ServicesDep，涉及揭示文件时加 dependencies=[LocalDep]；上传用 spool + read_chunks 并声明 openapi_extra=RAW_BODY。固定路径放在通配路由之前。
  3. 长操作返回 Job，进度靠事件；新的推送需要时在 core/events/models.py 加 EventBase 子类（它会自动进入 OpenAPI 和 ServerEvents），并在前端 api/socket.ts 处理。
  4. 若 CLI 也要提供同样的操作，调用同一个核心方法（见命令行实现）。
  5. 运行 python scripts/dev.py typegen 并提交 schema.d.ts（参数模型变了还有 paramSpecs.ts）；在 tests/api/test_api.py 用 TestClient 覆盖错误映射与权限。

核心服务

核心层（rvcnext/core/）是 RVC Next 的全部业务逻辑：任务调度、显存管理、资源下载、音色库与导入、转换、人声分离、训练、实时变声，以及它们共用的设置、事件和数据库。API 与命令行都只是它的薄外壳，引擎（rvcnext/engine/）只被它以函数调用的方式使用，且只在函数内部惰性导入 torch。

Web UI

Web UI 是 rvcnext/webui/ 下的一个 Vue 3 项目，同时也是一个 Python 包：构建产物 dist/ 被 git 忽略，作为包数据打进 wheel，由 API 的 SPAStaticFiles` 提供（见 API 与事件）。
