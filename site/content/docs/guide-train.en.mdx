Compared with the original RVC, rvc-next combines “process data → extract pitch → extract features → train → build index” into one workflow: **Run all** only runs stages that are incomplete or whose inputs have changed.

## Experiment list

Open **Train** in the left navigation to see cards for all experiments. Each card shows:

- The experiment name, with a **Running** label while active;
- Sample rate · model version · **One speaker** or **Several speakers**;
- Status labels for five stages: **Slice**, **Pitch**, **Features**, **Train**, **Index** (the primary color for completed stages, a warning color for **Out of date**, and red for **Failed**);
- **Last activity …**.

Click a card to open the experiment page. Experiments are stored under `experiments/` in the data folder (change this in **Settings › Storage › Experiments**). Experiment folders copied directly into this directory (containing `experiment.json`, or the original's `0_gt_wavs` folder) also appear automatically.

### New experiment

1. Click **New experiment**.
2. Enter an **Experiment name**.
3. Select **One speaker** or **Several speakers**. For one speaker, enter the **Dataset folder** directly or click **Browse…** to select a server folder (the table for several speakers is filled in on the experiment page).
4. Click **Add** to open the new experiment's page.

Initial values for sample rate, version, pitch guidance, epochs and other settings come from **Settings › Training defaults**.

<Callout type="info" title="Browsing server folders">

**Browse…** is available only when you open the page on the server machine or the server has an access token set. Otherwise, paste the server path directly into the field.

</Callout>
### Import an original RVC experiment

If you have already trained in the original RVC (experiments are under its `logs/<name>`), you can import the experiment and keep using it:

1. Click **Import experiment**.
2. Enter the path in **Original experiment folder (logs/&lt;name>)**. Optionally enter a new **Experiment name** (defaults to the folder name).
3. Click **Import**.

rvc-next **copies** the entire folder into the experiment directory (leaving the original untouched) and infers the sample rate, version, pitch guidance and completed stages from its contents. The folder must contain `0_gt_wavs` or `config.json`; otherwise, it reports that this does not look like an RVC experiment. Imported experiments do not record the original dataset folder. To slice again, enter it in the **Dataset** step first.

## Experiment page

The top of the experiment page shows its name, sample rate · version · folder path, with a **Delete** button on the right (unavailable while running; deleted experiments are moved to `trash/` in the data folder).

Below are four steps: **Dataset**, **Settings**, **Run**, **Results**. While running, an overall progress bar appears below the step bar, and **Run** indicates the current stage.

### Step 1: Dataset

<Tabs items={["One speaker", "Several speakers"]}>
<Tab value="One speaker">

1. Select **One speaker**.
2. Enter a path in **Dataset folder**, or click **Browse…** to select one.
3. Click **Save**.

Only audio files at the folder's **top level** are read; subfolders are not scanned.

</Tab>
<Tab value="Several speakers">

A dataset with several speakers is described by a **Speakers** table, with one speaker per row:

| Column | Description |
| --- | --- |
| **Name** | Speaker name; must be unique |
| **ID** | 0–109; must be unique (duplicates show **Duplicate ID N**) |
| **Folder** | This speaker's audio folder; click to select |
| **Repeat** | 1–100; how many times this speaker's data is repeated during training, to balance speakers with different amounts of data |

- Click **Add speaker** to add a row; delete a row to remove it.
- If your data already follows the original's `Name_ID_Repeat` subfolder convention (for example, `alice_0_1`, `bob_1_2`), click **Fill from Name_ID_Repeat folders** and select their parent folder to fill the table automatically. Each subfolder must follow this format, have an ID from 0–109 and a repeat count of at least 1, map each ID to only one name, and contain audio.

Click **Save** when finished. Exported voices include these speaker names.

</Tab>
</Tabs>

**Add audio from this computer**: drop audio files, or a zip of them, on the drop zone (or click it) to upload them into the experiment's own `dataset_upload/` folder; the dataset then points there, so a server you reach from another machine needs no folder of its own. With **Several speakers**, upload a zip whose top-level folders follow `Name_ID_Repeat` (as above): they become the speaker table. Uploads add to what is there; **Remove the uploaded audio** empties the folder. Zip members outside audio files, hidden files and `__MACOSX` are skipped.

**Clean the dataset first**: select a separation preset to run vocal separation on the whole dataset before slicing (for example, to remove accompaniment or reverb). Results are stored in the experiment's `dataset_clean/`; original files are unchanged. The default is **No clean-up**. Presets are the same as on **Separate**, and the required separation models must be downloaded first.

**Slicing** (opens on click) decides how the recordings are cut into training pieces. The defaults are the original's; the options come from Applio:

| Setting | Options (default) | Description |
| --- | --- | --- |
| **Cut** | At silences, then into pieces (default) / Into pieces, straight through / As they are (already cut) | The original finds the silences first and cuts the sound between them into pieces. Straight through keeps silences in the pieces. As they are suits a dataset you cut yourself; a file longer than the piece length + 5 s is still cut, since training would leave it out |
| **Piece length (s)** | 0.5–10; blank: 3.7 s with a GPU, 3.0 s without | Length of each piece |
| **Overlap between pieces** | 0–0.4 s (0.3) | How much consecutive pieces share |
| **Loudness** | Even out each piece (default) / Even out each file / Leave as recorded | The original brings every piece to the same peak; per file keeps the differences inside a recording; as recorded keeps the levels |
| **Noise reduction** | 0–1 (0) | A noise gate over each recording before it is cut, for noisy recordings; separating with **Clean the dataset first** removes more (music, reverb) |
| **Remove rumble (48 Hz high-pass)** | On / Off (On) | The original always filters; turn it off only for recordings already filtered |

Changing them marks **Slice** and every later stage out of date.

**Scan dataset**: this button scans the dataset and generates a report:

- **N clips**, **duration in total**;
- File counts for each **Sample rates** entry; with several speakers, clip counts for each speaker are also listed;
- A **Problems** list (**No problems found** when there are none):

| Problem | Criterion |
| --- | --- |
| **too short** | Shorter than 1 second |
| **too long** | Longer than 30 minutes |
| **clipped** | More than 0.1% of samples reach full scale |
| **silent** | Peak below −50 dBFS |
| **unreadable** | The file cannot be decoded |

<Callout type="idea" title="The scan uses the saved dataset">

**Scan dataset** reads the saved settings. After changing folders, click **Save** before scanning.

</Callout>
### Step 2: Settings

| Setting | Options | Description |
| --- | --- | --- |
| **Sample rate** | 32k / 40k / 48k | Sample rate for training and the exported voice |
| **Model version** | v1 / v2 | v2 uses 768-dimensional features and is recommended; v1 uses 256 dimensions |
| **Content features** | ContentVec (RVC, default) / SPIN / SPIN v2 / Chinese, Japanese, Korean HuBERT | The model that reads what is said. The others come from Applio: SPIN keeps less of the speaker's own voice in the features, the language HuBERTs suit those languages. All but ContentVec and SPIN are for v2 only. The voice records its choice, so conversion uses the same; the model downloads on first use (about 380 MB) |
| **Pitch method** | RMVPE (best) / pm (fast) / FCPE / CREPE / CREPE tiny / SwiftF0 | Method for extracting pitch from training data; unavailable when pitch guidance is off. New experiments default to RMVPE with an available CUDA GPU, otherwise pm. The original offers only pm and RMVPE for training; the others are the conversion methods of the same names (see [Pitch method](/docs/guide-parameters#f0)) |
| **Epochs** | ≥ 1 | Total training epochs |
| **Batch size** | ≥ 1; leave blank for **Automatic** | Automatic takes the smallest GPU's memory (GiB) ÷ 2, rounded down, as in the original; 1 without a GPU. It is per GPU: with two GPUs each one trains on this many clips at a time (the original gave each GPU this times the number of GPUs) |
| **Save every N epochs** | ≥ 1 | Number of epochs between checkpoints |
| **GPUs** | `auto`, `cpu` or GPU IDs such as `0-1` | GPUs used for training, saved in the experiment. New experiments use `training.gpus` from settings. `auto` uses all available CUDA GPUs; `cpu` uses only CPU |
| **Pitch guidance** | On / Off | When off, the trained voice has no pitch guidance (suited to speech rather than singing), and the **Pitch** stage is skipped |
| **Cache the dataset in GPU memory** | On / Off | Stores the entire training dataset in GPU memory; can speed up training for small datasets with enough GPU memory |
| **Save a voice at every save point** | On / Off | Saves a small, directly usable model in `weights/` alongside each checkpoint, for comparing different epochs |
| **Keep only the latest checkpoint** | On / Off | Keeps only one pair of G/D checkpoints (`G_2333333.pth`/`D_2333333.pth`, as in the original), saving disk space |
| **Render a sample at every save** | On (default) / Off | At every save, the voice as it is renders one training clip (the longest slice) into `previews/`; **Results › Samples** lists them |

Under **Advanced**:

| Setting | Options | Description |
| --- | --- | --- |
| **Precision** | Automatic / Full (fp32) / bf16 | Automatic trains in half precision (fp16, with loss scaling) when every chosen GPU supports it, as the original; bf16 needs no loss scaling and suits recent NVIDIA (RTX 30 series on), AMD and Intel GPUs (without bf16 support, training falls back to fp32 and says so in the log); fp32 is the slowest and the most exact |
| **TF32 maths** | On / Off | Lets NVIDIA GPUs from the RTX 30 series on use TF32 for full-precision matrix maths: faster, slightly less exact |
| **Save memory (gradient checkpointing)** | On / Off | Recomputes the generator's upsampling and residual blocks and each discriminator in the backward pass instead of keeping their activations: for GPUs with little memory, at the cost of slower steps |
| **New speaker vectors** | On / Off | Starts each speaker of the experiment from a new random vector (at the size of the base model's) instead of the base model's own; in every official base model speakers 0 and 1 have the same vector, so two speakers of a multi-speaker voice would start out alike. From Applio |

The fp16 loss scale is saved with the checkpoints, so a resumed run continues from it instead of starting the scale again. Trained voices carry the epoch, step and date, and the author from **Settings › Training › Author** when set; **About** on a voice's page shows them.

**Base model**: training starts from a base model.

- The default, **Chosen from the rate, version and pitch guidance**, uses the corresponding official base model.
- Base models imported in **Models › Base models** also appear here, but **Only base models of this rate, version and pitch guidance are listed.** Models without a discriminator (D) are marked **no D**. If a change to sample rate, version or pitch guidance makes the selected base model incompatible, the selection automatically returns to the default.

Click **Save** when finished. If required files have not been downloaded (official base models, HuBERT, and the RMVPE model when using RMVPE), the **Save** button is replaced by **Needs …** and **Download (size)**. Download them before saving.

### Which stages must rerun after settings change?

Each completed stage records an input “fingerprint.” After saving changes, affected completed stages are marked **Out of date**, with the message **Inputs changed since this stage ran.**

**Run all** also recalculates every completed stage's fingerprint. Even without changing settings on the page, adding, deleting or replacing recordings directly in the dataset folder causes slicing and all subsequent stages to rerun. Increasing only the **Epochs** continues training without rerunning earlier stages.

| Change | First stage marked out of date |
| --- | --- |
| Dataset folder or speaker table | Slice |
| Clean-up preset | Clean-up |
| Sample rate, **Slicing** | Slice |
| Pitch guidance, pitch method | Pitch |
| Model version | Features |
| Training parameters such as epochs or batch size | None (increasing epochs makes **Run all** continue training) |

Rerunning a stage also marks subsequent completed stages **Out of date**.

### Step 3: Run

**Run** lists cards for all stages:

| Stage | Purpose | When it runs |
| --- | --- | --- |
| **Clean-up** | Cleans the dataset with the selected separation preset | Only when a clean-up preset is selected |
| **Slice** | Splits audio at silence and resamples it into training clips | Always |
| **Pitch** | Extracts each clip's pitch with pm or RMVPE | Only with pitch guidance enabled |
| **Features** | Extracts content features with HuBERT | Always |
| **Train** | Trains the generator and discriminator, saving checkpoints as configured | Always |
| **Index** | Builds a retrieval index from features (`added_*.index`) | Always |

Each card shows its state (**Not run**, **Running**, **Done**, **Out of date**, **Failed**, **Skipped**), processed count and completion time, or an error message on failure.

- **Run all**: runs only incomplete, out-of-date or failed stages. If **Train** is done but you increased **Epochs**, it continues to the new epoch count. If all stages are done and inputs are unchanged, it reports that no stages need to run.
- A single stage: click **Run this stage** on its card. Completed stages show **Run again**, which forces another run.
- **Stop**: appears while running and cancels the current job. The cancelled stage returns to **Not run**; completed stages are kept.

<Callout type="info" title="Training resumes from the latest checkpoint">

When **Train** starts, if the experiment folder already contains G/D checkpoints, training resumes from the latest pair rather than starting over. Create a new experiment to train entirely from scratch.

</Callout>
While running, the **Run** step shows a job card and a progress bar appears below the step bar. The same job appears in the top-bar **Jobs** panel, where you can read its log. Training queues as a GPU job: if live voice conversion is using the GPU, it shows **Waiting for the GPU**. You can click **Run anyway** (which may cause live audio glitches).

### Step 4: Results

The **Loss** chart shows training loss curves (the horizontal axis is step). Total losses `g_total` and `d_total` come first, followed by components such as `mel`, `kl`, `fm` and `gen`. Curves update live during training. **Gradient norms** below shows `grad_g` and `grad_d`, the size of the generator's and the discriminator's gradients at each step: a sudden jump often comes before a run goes wrong.

**Samples** (with **Render a sample at every save** on) lists the training clip as the voice rendered it at each save, labelled by epoch; A/B plays the clip itself, so you can hear the voice approach it, and hear when more epochs stop helping.

**Checkpoints** lists the experiment's G checkpoints and small models (`.pth` files in `weights/`). Each entry shows its type, epoch count and file size:

- **Try**: sends this entry to **Convert** as a temporary voice (with the experiment's index), so you can immediately convert a clip and hear the result. Temporary voices do not appear in the voice library. G checkpoints are automatically extracted into small models first (stored in the experiment's `.try/` folder; each checkpoint is extracted only once).
- **Export as voice**: exports this entry to the voice library.

The **Export as voice** button at the top right of the list exports the latest result (preferring the latest small model, otherwise the latest G checkpoint).

### Export to the voice library

1. Click **Export as voice** (at the top of the list or beside a checkpoint).
2. Enter a **Voice name**, defaulting to the experiment name.
3. Click **Export**. When finished, it shows **Exported as a voice**.

During export:

- A selected G checkpoint is first extracted into a small model;
- The experiment's indexes (`added_*.index`) are attached to the new voice;
- Experiments with several speakers write the speaker names into the model.

The exported voice appears in **Models › Voices** and can be used in **Convert**, **Live** and other pages.

## Recommended workflow

1. Prepare at least 10 minutes of clean recordings without accompaniment and put them in one folder.
2. Create a **New experiment**, select the dataset folder, **Scan dataset**, and address problem files such as **clipped** or **silent** recordings.
3. In **Settings**, check the sample rate (40k is usually enough), version v2 and pitch guidance (required for singing).
4. Download the requested base models and other models, then **Save**.
5. Click **Run all** in **Run**, and watch the loss curves in **Results**.
6. With **Save a voice at every save point** enabled, **Try** small models from different epochs and **Export as voice** for the best one.
7. If the result needs improvement, increase **Epochs** and **Run all** again. Training resumes from the previous checkpoint.

## Command line

Training can also be done entirely from the command line, using the same experiments as the web UI:

```bash
rvc-next train new "My voice" --dataset D:/data/me --sr 40k --version v2
rvc-next train dataset scan "My voice"      # Scan the dataset
rvc-next train run "My voice" --epochs 200  # Run all stages
rvc-next train run "My voice" --stage index --force   # Rerun only the index
rvc-next train status "My voice"
rvc-next train export "My voice" --voice-name "My voice"
rvc-next train import D:/RVC/logs/old --name old      # Import an original experiment
```

See [Command reference](/docs/cli-commands) for more options.
