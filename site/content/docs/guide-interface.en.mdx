## Overall layout

The interface has three parts:

- **Navigation**: in wider windows, a vertical bar on the left lists **Convert**, **Live**, **Separate**, **Train** and **Models**, with **Settings** at the bottom. Below 600 pixels wide (for example, on a phone or in a narrow window), navigation moves to the bottom as a row of six buttons.
- **Top bar**: the application name **RVC Next** always appears on the left; the right contains the live status chip (only while live voice conversion is running), jobs button, GPU memory button and theme button.
- **Content area**: the current page. Only this area fades in and out when switching pages; navigation and the top bar stay still.

### What is kept when switching pages

- Each page **stays as you left it**: added inputs, selected voice, adjusted parameters and scroll position are preserved, so you can resume when you return.
- Navigation buttons return to your last location within that page. For example, if you open an experiment in **Train**, switch to **Convert**, then click **Train**, you return to that experiment.
- **Refreshing the browser resets** all temporary page state. Only actual preferences are saved: theme, last page, last voice selected in **Convert**, last preset selected in **Separate**, etc. These preferences are stored on the server, so they are the same in another browser.

## Page structure

Pages such as **Convert**, **Separate** and **Live** share the same structure:

1. **One column of sections**: arranged from top to bottom. For example, **Convert** contains **Inputs**, a voice and **Voice parameters**, then **Results**. Each section fills the page width, and its fields wrap automatically to fit.
2. **Bottom action bar**: fixed at the bottom of the page and visible wherever you scroll. It contains:
    - Errors from this page;
    - Cards for unfinished jobs started from this page (scrollable when there are multiple jobs);
    - Run buttons such as **Preview 15 s** and **Convert**. When unavailable, a short line on the left explains why, such as “Add audio to convert.” or “Choose a voice.”

### When models are missing [#missing-models]

If a model needed for the current operation has not been downloaded, the run button in the action bar is replaced by a notice such as “**Needs HuBERT, RMVPE**” and a **Download (353 MB)** button. Clicking shows download progress in place; the run button returns automatically when the download finishes. You do not need to remember which files each feature requires beforehand.

### When an error occurs

Errors appear where they occur (in the action bar, a job card or a dialog). The title is the translated error type (for example, “A required model file is not installed” or “The GPU is not available or ran out of memory”), followed by the server's specific message (in English). When more information is available, a **Details** button opens the full content, which you can include in a problem report.

## Jobs [#jobs]

Time-consuming operations such as conversion, separation, training, downloads, merging and extraction run as **jobs** on the server. Jobs are queued in the background without blocking the interface; they continue running even if you close the browser tab.

### Job cards

Job cards appear in the action bar of the page that started them and in the **Jobs** sheet. Each card shows:

- **Title**: generated by the server, currently in English, such as `Convert song.wav · kikiV1` or `Preview song.wav · kikiV1`;
- **Status**: **Queued**, **Waiting** (specifically **Waiting for the GPU**, **Waiting for the CPU** or **Waiting for a download**), **Running**, **Cancelling**, **Cancelled**, **Failed**, **Done** or **Interrupted**;
- The current step and the completed step count for multi-step jobs, such as `2/5`;
- A progress bar while running; download jobs also show downloaded/total size, speed and time remaining.

Buttons on the right of the card:

| Button | Purpose |
| --- | --- |
| **Cancel** (×) | Stop an unfinished job |
| **Retry** (↻) | Run the exact same request again; available for **Failed**, **Cancelled** and **Interrupted** jobs |
| **Log** | Expand or collapse this job's log inside the card; once opened, the button becomes **Hide log** |

A few special cases:

- **Interrupted**: if the server shuts down while a job is running, the job is marked interrupted at the next startup. Its request is saved, so you can **Retry** directly.
- **Run anyway**: while live voice conversion is using the GPU, new GPU jobs wait. The card shows “Live is using the GPU. Running both may cause audio glitches.” and offers a **Run anyway** button.
- **Preview priority**: preview jobs go ahead of other queued jobs to deliver results sooner.

### Jobs sheet and jobs page

Click **Jobs** in the top bar to open the **Jobs** sheet. When no jobs are running, the button shows a checklist icon; while jobs are running, the icon spins and a badge shows the running job count (the tooltip reads “N running”).

The sheet lists jobs from all pages: jobs started in this session (with live progress) come first, followed by recent history recorded by the server, up to 30 jobs. Click **All jobs** at the top right to open the full jobs page, where you can filter by **All**, **Active** or **Finished**, or click **Clear finished**.

When a job started on another page finishes or fails, a notification appears at the bottom of the screen, such as “… finished”. Failure notifications include an **Open log** button that opens the jobs sheet.

## Results list [#results]

**Convert** and **Separate** (and **Test** in voice details) use the same **Results** list. It shows only results from jobs **started on this page in the current session**, newest first. Refreshing the browser clears the list, but the files remain and can be found again through **Earlier results** in the input section.

Each result occupies one row, with:

- A **Play** button: all results share one player, so playing one stops the other;
- Filename, type label (**converted**, **remix**, **stem**, **preview**), stem name (such as `vocals`) and duration;
- **Waveform**: shows playback progress; click to jump to a position;
- **Result / Source** toggle: switch between converted and original audio at the same playback position for A/B comparison;
- **More actions** (⋮) menu.

Items in the **More actions** menu:

| Item | Purpose | When available |
| --- | --- | --- |
| **Download** | Download the file to the computer running the browser | Always |
| **Show in folder** | Locate the file in the server computer's file manager | When browser and server are on the same computer |
| **Use as input** | Add this result to the current page's inputs for another pass | Always |
| **Convert this** | Send this stem to **Convert** | Stem results |
| **Re-run with these settings** | Restore the voice and parameters used to generate it on **Convert**, and add its source file back to the inputs | Conversion results |
| **Delete** | Move the file to the system trash and remove its record | Always |

When there is more than one result, **Download all** appears at the top right of the list to download them as a zip.

## Handoffs between pages

Audio and voices can pass directly between pages without downloading and uploading them again:

- Choose **Convert this** on a **Separate** result: the stem is added to **Convert**'s inputs, and the interface switches to **Convert** automatically.
- Click **Earlier results** in any page's input section: select results from the full history to add as inputs.
- Click **Try** on a checkpoint in **Train**: a temporary voice is generated from the checkpoint, and **Convert** opens with that voice selected so you can try the training result directly.
- Choose **Re-run with these settings** on a **Convert** result: restore the voice and parameters used at the time.

## Other top-bar buttons

### GPU memory

The memory-module icon in the top bar shows GPU memory usage. Hover over it to see “GPU memory: used of total · Loaded: …” (or the device in use when there is no GPU). Its badge shows the number of models currently loaded in memory.

Click to open a menu with one item, **Free GPU memory**: unload all cached models, including HuBERT, voices and pitch models, and have PyTorch return GPU memory. It is available whenever no jobs or live voice conversion are running; otherwise, it is disabled and shows the reason, such as “Free GPU memory (wait: a job is running)”. Success is reported as “GPU memory freed”.

Models also unload automatically after an idle period, configured with “Unload models after idle minutes (0: never)” in **Settings › Compute**, defaulting to 10 minutes. When GPU memory runs out, RVC Next automatically unloads all models not currently in use and reports “The GPU is not available or ran out of memory”.

### Theme

The rightmost button cycles through **Light** → **Dark** → **System**, with its icon showing the current choice. More appearance options (**Colour**, **Contrast**, **Motion**) are in **Settings › Appearance**.

### Live status chip

While live voice conversion is running, a chip appears before the buttons on the right of the top bar, visible on every page. It shows “Live · N ms” (estimated latency) while running, or the current state during startup, loading or reconnection, such as “Loading the voice…” or “Reconnecting the device…”. Click the chip to open **Live**; click the square **Stop** button beside it to stop live voice conversion directly. See [Live voice conversion](/docs/guide-live).

## Access token

If the server has an access token set (for example, to allow access from other computers), an **Access token** dialog appears when the browser first connects; enter it to proceed. Some features are also available only to “trusted” browsers: for example, **Server files** in the input section appears only when browser and server are on the same computer, or when the server has an access token set. See [Remote access and security](/docs/advanced-remote).

## Keyboard controls

- <kbd>esc</kbd> closes the topmost dialog, menu or sheet (one layer at a time).
- Focus a drop zone with <kbd>tab</kbd>, then press <kbd>enter</kbd> or <kbd>space</kbd> to open the file picker.
- Focus a result's waveform with <kbd>tab</kbd>, then use <kbd>arrow-left</kbd> / <kbd>arrow-right</kbd> to move backward or forward by 5% at a time.
- Focus a clickable card (such as a preset in **Separate** or a voice in the library), then press <kbd>enter</kbd> to activate it.
- To reduce interface animations, select **Reduced** in **Settings › Appearance › Motion**.
