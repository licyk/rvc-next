All commands accept these two options, which are omitted from the tables below:

| Option | Description |
| --- | --- |
| `--debug` | Print debug logs |
| `--help` | Show this message and exit |

A "—" in the "Default" column means the option has no effect unless supplied, or inherits a value from a preset or settings (as explained in the description). Ranges are written as `[a, b]`.

## Root command

```text
rvc-next [OPTIONS] COMMAND [ARGS]...
```

Retrieval-based voice conversion: convert, live, separate and train.

| Option | Description |
| --- | --- |
| `--install-completion` | Install completion for the current shell |
| `--show-completion` | Show completion for the current shell, to copy it or customize the installation |

## Server and system

### `webui`

Start the server and open the Web UI.

```text
rvc-next webui [OPTIONS]
```

| Option | Description | Default |
| --- | --- | --- |
| `--host <str>` | Address to bind | From `server.host` in settings (`127.0.0.1`) |
| `--port <int>` | First port to try, `[0, 65535]`; `0` lets the system pick any port | From `server.port` in settings (`7868`) |
| `--strict-port / --no-strict-port` | Fail instead of trying the next port when the port is in use | From `server.strict_port` in settings (off) |
| `--open / --no-open` | Open the Web UI in a browser | From `server.open_browser` in settings (on) |
| `--data-dir <directory>` | Data directory (settings, database, models, outputs) | `RVC_NEXT_DATA_DIR` or the system default location |
| `--config-dir <directory>` | Folder for `settings.toml` | `RVC_NEXT_CONFIG_DIR` or the data directory |
| `--api-prefix <str>` | Serve the API, the socket and the Web UI under this path, e.g. `/voice` | None |

If the port is in use, subsequent ports are tried in order (up to 20), and the actual port is reported in the log. If all attempts fail, the command exits with code 3. Binding to a non-local address requires an access token first; otherwise the command exits with code 4 (see [Remote access and security](/docs/advanced-remote)). After a successful start, stdout prints one line: `SERVER_READY url=http://...`.

```bash
rvc-next webui
rvc-next webui --port 8000 --no-open
rvc-next webui --data-dir D:/rvc-next-data
```

## Conversion and separation

### `convert`

Convert audio files or folders with a voice. Parameters start from the voice's default preset, with command-line options overriding the corresponding values.

```text
rvc-next convert [OPTIONS] INPUTS...
```

| Argument | Description |
| --- | --- |
| `INPUTS...` | Audio files or folders (required; multiple allowed) |

| Option | Description | Default |
| --- | --- | --- |
| `-v, --voice <str>` | Voice ID, name, or `.pth` path (required) | — |
| `-o, --output <directory>` | Output folder | The job's folder in the data directory |
| `--preset <str>` | Start from this preset instead of the voice's default | The voice's default preset |
| `--index <file>` | Index for a `.pth` voice given by path | — |
| `--speaker <int>` | Speaker ID of a multi-speaker voice, `[0, 109]` | From the preset |
| `--pitch <float>` | Pitch shift in semitones, `[-24, 24]` | From the preset |
| `--formant <float>` | Formant shift in semitones, `[-2, 2]` | From the preset |
| `--f0 <str>` | Pitch method: `pm`, `rmvpe`, `fcpe`, `crepe`, `crepe-tiny` or `swift` | From the preset |
| `--index-rate <float>` | Index strength, `[0, 1]` | From the preset |
| `--protect <float>` | Consonant protection, `[0, 0.5]`; 0.5 turns it off | From the preset |
| `--rms-mix <float>` | Loudness match, `[0, 1]`; 1 keeps the converted loudness | From the preset |
| `--unvoiced <mode>` | Frames without pitch: `protect`, `zero` or `original`; see [Frames without pitch](/docs/guide-parameters#unvoiced) | From the preset |
| `--high-register <mode>` | RMVPE above about 1040 Hz: `off`, `true_pitch` or `fold`; see [Very high notes](/docs/guide-parameters#high-register) | From the preset |
| `--f0-ceiling <float>` | Highest pitch `true_pitch` writes, `[1000, 2000]` Hz | From the preset |
| `--separate <str>` | Separate first with this preset and convert the vocals | — |
| `--remix` | Add the accompaniment back (needs `--separate`) | Off |
| `--remix-gain <float>` | Accompaniment gain in dB | `0.0` |
| `--format <str>` | `wav`, `flac`, `mp3`, or `m4a` | `convert.output_format` in settings (`wav`) |
| `--resample <int>` | Resample the result to this rate, at least 16000 | The voice's own sample rate |
| `--recursive / --no-recursive` | Look into subfolders of folder inputs | `--no-recursive` |
| `--overwrite / --no-overwrite` | Replace existing files in the output folder | `--no-overwrite` |
| `--preview <float>` | Convert only the first N seconds, `[1, 120]` | — |
| `--json` | Print the finished job as JSON | Off |

When finished, prints output file paths one per line.

```bash
rvc-next convert vocal.wav -v "My voice" --pitch 12
rvc-next convert ./in --recursive -v kikiv1 --f0 fcpe -o ./out --format mp3
rvc-next convert song.flac -v ./voice.pth --index ./added.index --separate vocals --remix
```

### `separate`

Separate vocals, accompaniment, and reverb. Use a single preset or a chained preset.

```text
rvc-next separate [OPTIONS] [INPUTS]...
```

| Argument | Description |
| --- | --- |
| `INPUTS...` | Audio files or folders (required unless using `--list`) |

| Option | Description | Default |
| --- | --- | --- |
| `-p, --preset <str>` | Preset ID; see `--list` | `separation.default_preset` in settings (`vocals`) |
| `-o, --output <directory>` | Output folder | The job's folder in the data directory |
| `--format <str>` | `wav`, `flac`, `mp3`, or `m4a` | `separation.output_format` in settings (`flac`) |
| `--recursive / --no-recursive` | Look into subfolders | `--no-recursive` |
| `--list` | List the presets and exit | Off |
| `--json` | Print JSON | Off |

Built-in presets: `vocals`, `vocals-aggressive`, `dereverb`, `dereverb-aggressive`, `karaoke`, and the chained presets `vocals-clean` (vocals → dereverb) and `lead-clean` (vocals → lead vocals → dereverb). Imported separation models use `user-<name>` as their preset ID.

```bash
rvc-next separate --list
rvc-next separate song.mp3 -p vocals-clean -o ./stems
```


### `model import`

Import models. Each file is identified by content; pairing indexes with voices does not depend on file names.

```text
rvc-next model import [OPTIONS] PATHS...
```

| Argument | Description |
| --- | --- |
| `PATHS...` | Voices (`.pth`), indexes, `.zip` archives, base models (G/D), separation models (`.ckpt` + `.yaml`), folders, or an RVC installation (required) |

| Option | Description |
| --- | --- |
| `--name <str>` | Name for a single imported voice |
| `--index <path>` | An `.index` to attach to a single voice, whatever its name |
| `--pair <str>` | Pair by file name: `VOICE.pth=FILE.index[:spkN]`; repeat for several |
| `--keep-unassigned` | Put indexes that cannot be paired with certainty into the unassigned list |
| `--extract` | Turn training generators (G) into voices instead of importing them as base models |
| `--json` | Print JSON |

If an index's pairing is uncertain or a separation checkpoint lacks its configuration, the command prints file and index tables (including compatible voices), then exits with code 3 without importing any files. Given the root directory of an RVC installation, it copies `assets/weights/*.pth` and `added_*.index` files under `assets/indices` and `logs`.

```bash
rvc-next model import voice.zip
rvc-next model import model.pth --index ./whatever.index --name "My voice"
rvc-next model import a.pth b.pth x.index y.index --pair a.pth=x.index --pair b.pth=y.index
rvc-next model import G_2333333.pth D_2333333.pth            # Import as base models
rvc-next model import G_2333333.pth --extract --name "Experiment"   # Extract a voice
```

### `train run`

Run stages: without a selection, run all unfinished stages (or those whose inputs have changed); optionally run only selected stages.

```text
rvc-next train run [OPTIONS] NAME
```

| Argument | Description |
| --- | --- |
| `NAME` | Experiment name (required) |

| Option | Description | Default |
| --- | --- | --- |
| `--stage <str>` | `clean`, `slice`, `f0`, `features`, `fit`, `index`, or `all`; repeat for several | All stages that need to run |
| `--epochs <int>` | Total epochs, at least 1 | Saved experiment value (new experiments use `training.epochs`, 20) |
| `--batch-size <int>` | Batch size, at least 1 | Saved experiment value (auto: half the smallest GPU's memory in GiB) |
| `--save-every <int>` | Save every N epochs, at least 1 | Saved experiment value (new experiments use `training.save_every`, 5) |
| `--gpus <str>` | `auto`, `cpu`, or GPU IDs like `0-1`; saved in the experiment | Saved experiment value (new experiments use `training.gpus`, `auto`) |
| `--force / --no-force` | Run the chosen stages even when their inputs are unchanged | `--no-force` |
| `--base <str>` | Base model ID (see `rvc-next model list --type base`); saved in the experiment | Automatically selected by sample rate, version, and pitch guidance |
| `--precision <str>` | `auto` (fp16 when every GPU supports it), `fp32` or `bf16`; saved | Saved in the experiment (`auto`) |
| `--tf32` / `--no-tf32` | TF32 maths on NVIDIA GPUs; saved | Saved in the experiment (off) |
| `--checkpointing` / `--no-checkpointing` | Gradient checkpointing: less GPU memory, slower steps; saved | Saved in the experiment (off) |
| `--fresh-speakers` / `--no-fresh-speakers` | New speaker vectors instead of the base model's; saved | Saved in the experiment (off) |
| `--samples` / `--no-samples` | Render a training sample at every save; saved | Saved in the experiment (on) |

`--epochs`, `--batch-size`, `--save-every`, and `--base` are written into the experiment's training settings. After increasing `--epochs`, running without `--stage` runs the fit stage again even if it was already completed.

```bash
rvc-next train run alice
rvc-next train run alice --stage fit --epochs 300 --batch-size 6
rvc-next train run alice --stage index --force
```

### `live latency`

Measure the real latency of the saved devices with a loopback: connect the output to the input first (a cable, a virtual cable's loopback, or speakers near the microphone). Plays four noise bursts on the output, finds them in the input and prints the measured round trip, the converter's own delay, their sum and the estimate for comparison. Live must be stopped. Exits with code 1 when no burst comes back or the bursts disagree, and 8 when a device cannot be opened.

```text
rvc-next live latency [OPTIONS]
```

| Option | Description | Default |
| --- | --- | --- |
| `--block-ms` | Block length in ms | The saved one |
| `--level-db` | Peak level of the test bursts, −40 to −3 dBFS | `-12` |
| `--json` | Print JSON | Off |

### `live test-tone`

Play a short test tone on an output device.

```text
rvc-next live test-tone [OPTIONS] [DEVICE]
```

| Argument | Description | Default |
| --- | --- | --- |
| `DEVICE` | Output device ID, name, or `default` | `default` |

### `live run`

Convert live with the server's devices until <kbd>ctrl</kbd>+<kbd>c</kbd>, with one status line in the terminal.

| Option | Description | Default |
| --- | --- | --- |
| `-v, --voice <str>` | Voice ID or name | The last voice used |
| `--input <str>` | Input device ID, name, or `default` | Saved device |
| `--output <str>` | Output device ID, name, or `default` | Saved device |
| `--monitor <str>` | Monitor output ID, name, `default`, or `none` | Saved setting |
| `--preset <str>` | Start from this preset | Last parameters for the same voice; otherwise the voice's default preset |
| `--speaker <int>` | Speaker ID of a multi-speaker voice, `[0, 109]` | From the starting parameters |
| `--pitch <float>` | Pitch shift in semitones, `[-24, 24]` | From the starting parameters |
| `--formant <float>` | Formant shift in semitones, `[-2, 2]` | From the starting parameters |
| `--f0 <str>` | Pitch method: `pm`, `rmvpe`, `fcpe`, `crepe`, `crepe-tiny` or `swift` | From the starting parameters |
| `--index-rate <float>` | Index strength, `[0, 1]` | From the starting parameters |
| `--protect <float>` | Consonant protection, `[0, 0.5]`; 0.5 turns it off | From the starting parameters |
| `--rms-mix <float>` | Loudness match, `[0, 1]`; 1 keeps the converted loudness | From the starting parameters |
| `--unvoiced <mode>` | Frames without pitch: `protect`, `zero` or `original`; see [Frames without pitch](/docs/guide-parameters#unvoiced) | From the starting parameters |
| `--block-ms <int>` | Block length in milliseconds, `[20, 1500]` | Saved value (250) |
| `--crossfade-ms <int>` | Crossfade in milliseconds, `[10, 150]` | Saved value (50) |
| `--context-ms <int>` | Extra context in milliseconds, `[50, 5000]` | Saved value (2500) |
| `--threshold-db <float>` | Input gate in dB, `[-60, 0]`; -60 turns it off | Saved value (-60) |
| `--denoise-strength <float>` | Noise reduction strength, `[0, 1]` | Saved value (0.9) |
| `--phase-vocoder` / `--no-phase-vocoder` | Phase-vocoder crossfade between blocks | Saved value (off) |
| `--input-gain <float>` | Input level in dB, `[-24, 24]` | Saved value (0) |
| `--record <source>` | Record the session to the outputs folder once it runs: `both` (stereo, input left), `converted` or `input`; the file is printed when Live stops | Not recorded |
| `--allow-fallback` | Start even if the saved output device is missing and the default would be used | Off |
| `--seconds <float>` | Stop after this many seconds | Until <kbd>ctrl</kbd>+<kbd>c</kbd> |

Device names can be full names or substrings, as long as they match exactly one device. If multiple devices match, use an ID from `live devices`. After starting, the devices, buffering parameters, voice, and voice parameters are saved as defaults for next time.

```bash
rvc-next live run -v "My voice" --pitch 12 --block-ms 400
rvc-next live run --input "USB Microphone" --output "CABLE Input" --monitor none
```
